# 独立提示词与 Agent 装配链（2026-11-24）

> 面向维护者的设计说明：LLM 配置自带的提示词如何装载到 Agent，装配顺序如何保证不破坏既有提示词，以及只读装配链视图的数据契约。

## 一、要解决的问题

同一份 Agent 提示词，在不同 LLM 配置下可能需要不同的“人格/策略前缀”。过去只能改 Agent 的 DB 模板（`agent_prompts`），这会让所有配置共享同一份正文，也无法解释“这段提示词到底从哪来、插在哪”。

本能力做两件事：

1. **LLM 配置级独立提示词**：`llm_profiles.prompt` + `prompt_mode` + `prompt_apply_inherited`。配置装载到某个 Agent 时，按选定位置把这段纯文本并入该 Agent 的 system prompt。
2. **只读装配链**：`GET /api/agents/{key}/prompt/chain` 返回当前 LLM 解析、每个提示词段的来源/可编辑性/门控/字符数、工具/MCP/Skill 的静态清单，以及运行时注入点。前端据此画出“从 LLM 配置到 Agent 最终请求”的全链路。

## 二、数据模型

`schema.sql` 以幂等 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 增加三列（默认空/关闭，旧库零行为变化）：

| 列 | 类型 | 约束/语义 |
|---|---|---|
| `prompt` | `TEXT NOT NULL DEFAULT ''` | 纯文本，不渲染 `{{.Var}}`；长度 ≤ 8000 |
| `prompt_mode` | `TEXT NOT NULL DEFAULT ''` | `'' / prepend / append / replace`；与 `prompt` 同时为空或同时非空 |
| `prompt_apply_inherited` | `BOOLEAN NOT NULL DEFAULT false` | 仅在“非显式选择”的解析路径（任务链/全局）下是否也生效 |

`db/config.go` 把这三列从热路径的 `profileCols` 中**排除**，由独立的 `ProfilePrompt` / `ProfilePrompts` / `SetProfilePrompt` 读写。原因：`llm_profiles` 的常规扫描在每次模型调用前发生，把 8KB 文本塞进热路径既浪费带宽也容易让列序与 `scanProfile` 错位。保存配置时用影子指针（`*string` / `*bool`）区分“未提交该字段”和“显式清空”，避免只改模型名时把长提示词清掉。

## 三、装配顺序

`agent/prompt.go` 的 `renderSystemSegments` 是唯一装配点，运行时与只读预览共用：

```
正文（DB 模板优先，否则内置默认）
  + 技能索引（SkillIndexBlock，宿主注入）
  + 独立提示词（按 mode）
  + 代码硬尾巴（各 Agent 自己追加）
```

三种 mode 的精确语义：

- **prepend**：`P + "\n\n" + 正文 + 技能索引`，代码硬尾巴照旧追加。P 在正文最前。
- **append**：`正文 + 技能索引 + "\n\n" + P`，代码硬尾巴仍在其后。P 不是最后一段。
- **replace**：`P + 技能索引`，正文段标记为 `present=false`；技能索引与代码硬尾巴保留。不是“清空整个 system”。

未配置（`Text == ""` 或 mode 非法）时走原来的字符串拼接路径，逐字节不变。纯文本意味着 `{{.Goal}}` 不会被渲染——这是刻意选择：LLM 配置的提示词不应依赖某个 Agent 的模板变量。

`PromptSegment` 与 `JoinPromptSegments` 让预览与运行时共享同一批常量/函数；`StaticTailSegments` 与 `workerSystemWith` / `plannerSystemWith` / `mainAgentSystemWith` 的代码尾段保持同源，测试 `TestStaticTailSegmentsMatchRuntime` 防止漂移。

## 四、生效规则

| 解析路径 | 独立提示词是否生效 |
|---|---|
| Agent 显式绑定（`agents.llm_profile_id`） | **始终生效** |
| 会话 pin（`conversations.llm_profile_id`） | **始终生效**（显式选择） |
| 任务 LLM 链 / 全局激活配置 | 仅当该配置 `prompt_apply_inherited=true` 且解析可用 |
| 预览参数 `profile_id` | 只读预览使用；不改变运行时 |

`server/llm_profile_prompt.go` 把这层语义收敛成 `profilePromptForTaskRole` / `profilePromptForChat`；planner/worker/mainagent 是长生命周期对象，用每实例 resolver（`SetProfilePromptResolver`），因为一个 run 内 system prompt 只构建一次；chat/goals 是一次性调用，用 ctx overlay（`WithProfilePrompt`）。

选路优先级仍由既有的 `taskLLMRuntime.current()` / `effectiveProfileForAgent` 决定；本能力只在“已经选中的配置”上叠加文本，不改变模型选择、故障转移或额度逻辑。故障转移开启时实际服务方可能切换，但提示词不会跟着切换——装配链的 warnings 会明示这一点。

## 五、只读装配链 API

`GET /api/agents/{key}/prompt/chain?profile_id=<可选预览>`：

- `llm`：当前解析到的配置、模型、来源、独立提示词模式/字符数/是否生效。
- `segments[]`：`key/title/kind/source/source_label/editable/gate/present/available/reason/order/chars/text`。`kind` 为 `body | skill_index | profile_prompt | code_tail | host | runtime | finding_guidance | deferred_tools`。
- `tools`：内置/自定义/流量/Shell 分组、延迟工具名、排除项与原因、总数。
- `mcp[]`：来自 `mcp_tools_cache` 的只读清单（transport/mode/health/tool_count/cache_stale/tools）。
- `skills[]`：名称/描述/是否进索引/门控它的 MCP。
- `totals`：段数、字符数、估算 token（`(chars+1)/2`）。
- `warnings`：故障转移、MCP 健康、缓存过期等。
- `static_only: true`：不建 provider、不连接 MCP、不返回凭据。

运行时注入点（任务约束、Program Profile、登录凭据、意图快照、既有事实、终态经验、autopilot、启动指令、证据纪律、延迟工具）只返回门控与原因，`present=false`，正文永不在静态视图展开。

## 六、前端

- Agent 编辑器新增“全链路”Tab（只读），采用**门控信号流（Gate Flow）**：纵向 2px 主干 + 34px 工位行；左侧 LLM 解析梯（三步解析 + 继承闸门 + 可复制证明串）与 Skill 轨，右侧 Tools/MCP 轨；门控药丸画在行间缺口，不画成卡片。
- 行状态用线型独立编码：实线=已装配、4-3 虚线=门控投影（未生效）、1-3 点线+斜纹=运行时未知；来源色只做身份（左条 + 字母标签），不承担状态。独立提示词的 `prepend/append/replace` 用 `ƒ+ / ƒ− / ƒ!` 变换记号区分；`replace` 的正文行加删除线与 `SUPERSEDED <chars>`。
- 首个代码尾段之前画 2px `TERMINAL` 硬边界，标注“配置层止于此处”；隔离架（未进入主干的工具、索引外 Skill）常驻，不折叠进 tooltip。
- 顶部装配态势带：`AGENT / PROFILE / OVERLAY / SCALE / INTEGRITY / RUNTIME` 六单元 + 指示灯（只点亮真实异常；`LAMP TEST` 一次性全亮自检）。`SNAPSHOT` 在 API 未提供快照时间时写“未采集”，不画假实时、不轮询。
- 左右轨与 MCP 架、隔离架的纵向位置和整图高度均由内容计算，不写死坐标；SVG 固定 1200 基准并横向滚动，不压缩进手机宽。
- LLM 配置抽屉新增独立提示词编辑区：位置三选、继承开关、8000 字符校验、字符/token 估算、绑定 Agent 反查。
- 配置列表对已配置独立提示词的 profile 显示“独立提示词”徽章。

## 七、验证

- `agent`：三模式顺序、代码尾段在 P 之后、未配置逐字节不变、静态尾段与运行时一致、ctx 往返。
- `db`：幂等迁移、默认值、CHECK 约束（pair/len/mode）、DB 往返、`SaveProfile` 不改 prompt。
- `server`：归一化/清空/超长拒绝、chat 解析、链 API 处理器、保存三态与继承解析。
- 构建：`go build ./...` + 容器内 `next typegen && tsc --noEmit && next build`。
- 全量 `go test -p 1 ./...`（独立 PG）。

## 八、边界与已知限制

- 独立提示词是纯文本，不参与模板变量；需要变量时仍应改 Agent 的 DB 模板。
- `replace` 只替换正文，不替换技能索引与代码硬尾巴；这是安全边界，防止配置层绕过平台硬约束。
- 普通 LLM 配置本身不绑定 Agent；未绑定时只有 `prompt_apply_inherited=true` 才会在任务链/全局路径生效。
- 链 API 是静态投影：MCP 工具清单来自缓存，可能过期；运行时可能为空。`warnings` 会标注。
- 一个 run 内 system prompt 只构建一次；任务链推进/故障转移不会热更新已构建的提示词。
